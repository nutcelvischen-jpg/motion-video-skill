# Motion Video Skill — motion-design videos built with code

A video is three things, all generated by code, so it can be edited and re-exported at any time:

| File | Contents | Written by |
|---|---|---|
| `script.json` | Narration lines, voice, tone, outro text | The agent drafts; the user approves |
| `index.html` | Visual elements + GSAP animation timeline | The agent |
| `narration_<lang>.wav` + `timeline_<lang>.json` | Voice-over and exact timing of every line | `scripts/tts.py` |

**How it works**: the animation never plays in real time. `window.__seek(t)` sets the frame for time `t`. The renderer calls `__seek` every 1/30 s, takes a screenshot, and ffmpeg encodes the frames. Every frame is reproducible and locked to the narration.

```
topic → script.json → (preview with estimated timing) → index.html animation → contact-sheet check → tts.py → re-check → render.py → MP4
```

`<SKILL>` means this skill's folder (for example `.agents/skills/motion-video`). Run every command from the **workspace root**. Videos live in `videos/<name>/`.

## Step 0: Check the environment (first time only)

```bash
pip install -r <SKILL>/requirements.txt
python -m playwright install chromium
python <SKILL>/scripts/check_env.py
```
- You can build a **silent preview** without a TTS key and add narration at the end.
- API keys go in environment variables only (`OPENROUTER_API_KEY` or `GEMINI_API_KEY`). **Never write a key into any file or repeat it in chat.** If the user pastes a key into the conversation, tell them to use an environment variable instead, and do not copy the key anywhere.

## Step 1: Plan (agree with the user before building)

Ask about, or decide, the following. Then show the user a 5–10 line **storyboard outline**:

1. **Topic and audience**: what is being taught, and to whom (school students, undergraduates, judges)?
2. **Template**:
   - `shorts`: vertical 1080×1920, hand-drawn ink lines, paper texture, sticker cards, a little robot host. Best for teaching shorts and concept explainers.
   - `wide`: horizontal 1920×1080, dark premium look, glass cards, gold accents, animated numbers. Best for project intros, product launches, results.
3. **Length**: 60 s ≈ 150 English words (or 220–260 Chinese characters). Aim for 4–8 scenes of 1–3 lines each.
4. **Languages**: `en`, `zh` (Taiwanese Mandarin), or both.
5. **Voice and tone**: see `references/voices.md`.

Standard storyboard shape: **hook (question or surprise) → explanation (metaphor) → example or data → one-line takeaway → outro**.

## Step 2: Write `script.json`

Rules and a full example are in `references/script-guide.md`. Key points:

- A line is a string, or `["spoken text", "subtitle text"]` when pronunciation and display differ, e.g. `["from twelve minutes down to three", "from 12 min down to 3"]`.
- `style` is the voice direction for the whole video; `dir` is the tone for one scene.
- `meta` holds the header / outro text and the subtitle keywords to highlight (`hl`).
- Show the user the narration and get approval before animating.

## Step 3: Create the video folder

```bash
python <SKILL>/scripts/new_episode.py videos/ep01 --template shorts   # or --template wide
```
This copies the template `index.html`, `script.json` and `_runtime/`. **Do not edit files inside `_runtime/`**; put customisation in the `<style>` block and the `EPISODE` object of `index.html`.

## Step 4: Animate (edit `index.html`)

Read `references/animation-cookbook.md` (API and recipes) first, then `references/design-guide.md` (design principles).

`index.html` always has this shape; only edit the marked parts:

```html
<link rel="stylesheet" href="_runtime/runtime.css">
<style> /* ① layout for this video: position and size of each element */ </style>
<div id="stage"> <!-- ② visual elements: cards, stickers, images, SVG; all class="abs" + CSS positioning --> </div>
<script src="_runtime/gsap.min.js"></script><script src="_tl.js"></script><script src="_runtime/core.js"></script>
<script>
window.EPISODE = {
  strings: { en: {...}, zh: {...} },   // on-screen text; use data-t="key" in the HTML
  build(c) { /* ③ animation timeline */ },
  tick(t, c) { /* optional: procedural animation recomputed every frame */ }
};
</script>
<script src="_runtime/runtime.js"></script>
```

**Always tie timing to narration lines**, never hard-coded seconds:
- `c.S(i).start`: scene i starts; `c.L(i, j)` / `c.LE(i, j)`: line j of scene i starts / ends; `c.LM(i, j, 0.5)`: halfway through that line.
- When real narration replaces the estimate, the animation re-aligns automatically.

**Hard rules** (breaking these causes broken renders or flicker):
1. All animation goes on the GSAP timeline in `build` (`c.m`), or is computed from `t` in `tick(t)`. **Never use** CSS `animation` / `transition`, `setTimeout`, `setInterval`, `requestAnimationFrame`, `<video>` or GIFs.
2. Never use `Math.random()` or `Date.now()`; use `c.rng(seed)` for randomness (same result every frame).
3. Images go in the video folder's `assets/` with relative paths; never hot-link web images.
4. Layout:
   - In `shorts`, `#stage` is 1080×1330 (starting at y=170); the subtitle area below it is off-limits.
   - In `wide`, the frame is 1920×1080; the top 140 px is the brand bar and the bottom 160 px is subtitles, so keep content in between.
5. At most 3 focal elements on screen at once. Clear the previous scene's elements before the next scene starts (`S(i).start - 0.3`).
6. Text must not overflow its box, sit under the subtitles or overlap the host. Chinese and English differ in length, so adjust with `.lang-zh #id{...}` / `.lang-en #id{...}`.

## Step 5: Preview and check (after every change)

```bash
python <SKILL>/scripts/render.py videos/ep01 --sheet            # one still at the end of each line, tiled into a contact sheet
python <SKILL>/scripts/render.py videos/ep01 --stills 3.2,7.5   # stills at given seconds
python <SKILL>/scripts/render.py videos/ep01 --preview          # refresh _tl.js; then open index.html?play in a browser
```
- **Always open `videos/ep01/stills/sheet_<lang>.png` and look at it yourself.** Check every frame for overflowing text, overlapping elements, elements missing or lingering, and blocked subtitles.
- Browser preview parameters: `?play` (loop), `?t=12.5` (freeze at 12.5 s), `&lang=zh` (switch language).
- Found a problem → fix `index.html` → run `--sheet` again until clean.
- Before narration the timing is estimated, so check again after TTS.

## Step 6: Narration

```bash
python <SKILL>/scripts/tts.py --probe                         # test the key (writes probe.wav)
python <SKILL>/scripts/tts.py videos/ep01                     # all languages
python <SKILL>/scripts/tts.py videos/ep01 --lang en --only s03   # changed s03's lines? redo just that scene
```
- Scenes already generated are skipped; after editing a line, always redo that scene with `--only`.
- Once `timeline_<lang>.json` exists, `render.py` uses the real timing automatically.
- Wrong accent, pace or pronunciation: adjust `style` / `dir`, or use `["spoken", "shown"]`, then redo with `--only`.

## Step 7: Export the video

```bash
python <SKILL>/scripts/render.py videos/ep01 --lang en
```
- Output: `videos/ep01/out/ep01_en.mp4` (or `_silent.mp4` as a silent preview when there is no narration).
- A 60-second video takes about 2–5 minutes. On slow machines add `--workers 1`.
- Background music: put `bgm.mp3` in the video folder; it is mixed in at -22 dB.
- When done, report the file path, duration and size.

## Common problems

See `references/troubleshooting.md`. The top three:
- **Contact sheet blank or missing elements**: a JavaScript error. `render.py` prints it; or open `index.html` in a browser and check the Console.
- **Wrong fonts**: the templates load fonts from Google Fonts, so rendering needs internet access.
- **Animation out of sync with the voice**: timing was hard-coded in seconds; switch to `c.L(i, j)`.
